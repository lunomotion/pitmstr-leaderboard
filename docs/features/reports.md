# Reports & Certificates

PITMSTR generates five document outputs on demand, all server-rendered PDFs (plus one ZIP). This page lists each one, who triggers it, and from which screen. For how the documents are laid out see [PDF & Report Generation](../subsystems/pdf-reports.md); for endpoint specifics see [API: reports](../api/reports.md).

## At a glance

| Document | Endpoint | Triggered from | Format | Auth |
|---|---|---|---|---|
| Charter invoice | `GET /api/reports/invoice` | Admin billing dashboard | PDF (`attachment`) | `admin:access` |
| Payment package | `GET /api/reports/payment-package` | Admin billing dashboard | ZIP (invoice + vendor docs) | `admin:access` |
| Event results | `GET /api/reports/event-results` | Admin reports page | PDF (`inline`) | `admin:access` |
| QR turn-in sheet (one team) | `GET /api/reports/qr-sheet` | Admin reports page | PDF (`inline`) | `admin:access` |
| QR turn-in sheets (all teams) | `GET /api/reports/qr-sheet-batch` | Admin reports page | PDF (`inline`) | `admin:access` |

All five require an authenticated admin: each route begins with `requirePermission("admin:access")` and returns the guard's `401`/`403` response if it fails.

!!! warning "Verify: certificates are not implemented"
    This page's title and the documentation outline mention "certificates," but there is no certificate generator anywhere in `src/`. The only "certificate" reference in the codebase is the **Certificate of Insurance** vendor document type (`src/lib/types.ts`), which is an uploaded file bundled into the payment package, not a generated PDF. If a competitor/award certificate document is expected, it has not been built yet.

## Invoice PDF

- **Endpoint:** `GET /api/reports/invoice?invoiceId=...`
- **Generated by:** admin, from the billing dashboard row action. The link is `href={`/api/reports/invoice?invoiceId=${inv.id}`}` in `src/app/admin/billing/page.tsx`.
- **What it does:** loads the invoice (`getInvoice`), resolves the charter name/state (`getSchool`), and builds per-team line items by filtering all teams to the charter (`searchTeams("")` then `t.schoolId === invoice.charterId`), each at `CHARTER_FEE`. Renders the `InvoicePDF` template.
- **Returns:** `application/pdf` as an `attachment` named `NHSBBQA-Invoice-{invoiceNumber}.pdf`.

## Payment package (ZIP)

- **Endpoint:** `GET /api/reports/payment-package?invoiceId=...`
- **Generated by:** admin, from the billing dashboard row action (`href={`/api/reports/payment-package?invoiceId=${inv.id}`}`).
- **What it does:** renders the same `InvoicePDF`, then fetches active vendor documents (`getVendorDocuments`) and downloads each file, zipping everything together with [JSZip](https://stuk.github.io/jszip/). Files are numbered: `1-Invoice-....pdf`, then `2-...`, `3-...` for each vendor doc (file name derived from `doc.type`). A vendor doc that fails to download is skipped.
- **Why it exists:** school finance departments require supporting paperwork (W-9, ACH, Certificate of Insurance, Sole Source, Procurement, District Adoption) alongside the invoice. The package bundles the invoice plus all six in one download.
- **Returns:** `application/zip` as an `attachment` named `NHSBBQA-PaymentPackage-{invoiceNumber}.zip`.

!!! note "Vendor documents are managed separately"
    The six vendor docs are uploaded under `/admin/billing/documents` and stored in the Airtable Vendor Documents table (`type`, `fileName`, `fileUrl`, `active`). Only active docs are included. If none are uploaded, the package contains just the invoice.

## Event results PDF

- **Endpoint:** `GET /api/reports/event-results?eventId=...&teamsPerPage=10&topN=0`
- **Generated by:** admin, from `/admin/reports` (`src/app/admin/reports/page.tsx`), report type "event-results". The page lets the admin pick `teamsPerPage` (5, 10, or 25) and `topN`, then opens the URL in a new tab.
- **What it does:** loads the event (`getEvent`), the overall leaderboard (`getEventLeaderboard`), and the raw MEAT component averages from the Turn-Ins table (`fetchTurnInComponents`, which averages `MEAT_M/E/A/T` per team per category). It maps these into `TeamEventScore[]` and renders the `EventReport` template (overall standings + per-category pages).
- **Returns:** `application/pdf` as `inline` named `Event_Report_{eventName}.pdf`.

## QR turn-in sheet, single team

- **Endpoint:** `GET /api/reports/qr-sheet?teamId=...&eventId=...`
- **Generated by:** admin, from `/admin/reports`, report type "qr-sheet" (requires selecting a team).
- **What it does:** loads the team and event, resolves the school district (`getSchool`), and calls `generateTeamQRSheet` with the event's categories (excluding "Overall"). Renders `QRTurnInSheet`: a check-in code plus one code per category, sized for cutting and taping onto turn-in boxes.
- **Returns:** `application/pdf` as `inline` named `QR_Sheet_{team}_{event}.pdf`.

## QR turn-in sheets, all teams (batch)

- **Endpoint:** `GET /api/reports/qr-sheet-batch?eventId=...`
- **Generated by:** admin, from `/admin/reports`, report type "qr-bulk".
- **What it does:** fetches every team linked to the event (reads the Airtable Events record's `Teams` links, then each Team and its Charter), generates a QR sheet for each, and renders a single multi-page PDF (`BatchQRSheet`, one page per team). Print once, cut, distribute.
- **Returns:** `application/pdf` as `inline` named `QR_Sheets_All_Teams_{event}.pdf`.

## Where reports are triggered

```text
/admin/billing            -> Invoice PDF, Payment Package (per invoice row)
/admin/billing/documents  -> manage the vendor docs that feed the payment package
/admin/reports            -> Event results, QR sheet (single), QR sheets (batch)
```

The reports page builds the query string and calls `window.open(url, "_blank")` so the PDF previews/downloads in a new tab.
